# 管理长期记忆

长期记忆用于保存值得在后续对话中持续参考的信息，例如群内约定、活动安排和成员个人偏好。同一群聊共享一份群记忆，每个私聊会话各自独立保存；切换人格、模型或渠道后，当前会话的长期记忆仍会继续沿用。

## 开启对话中的记忆

在 Web Admin 的 **“LLM 工坊 → LLM 配置 → 对话与上下文”** 中开启长期记忆注入（`settings.runtime.memory_enabled`），点击“保存草稿”并“应用到 Bot”。日常也可由群管理员在群内发送 `/llm memory on` 按群开启，或在私聊中由会话本人直接开启。

开启记忆注入后，Bot 会在每轮回答前自动检索与当前话题相关的记忆，把精简目录和命中的正文片段附入当轮上下文；即使未开启工具调用，这部分自动召回也会生效。若希望模型在对话中自主新增、修订或删除记忆，则需同时开启全局工具调用（`settings.runtime.tool_calling_enabled`），并允许 `list_memories`、`read_memory`、`write_memory`、`delete_memory` 四个工具（默认工具集已包含这四项；若使用 `enabled_mode = "replace"` 自定义白名单，请手动将它们加入）。

开启工具后，模型会根据对话内容自行判断哪些信息值得记录——你既可以在聊天中自然地说“记一下周六晚八点联机”“上次约的时间改到周日”，也可以直接使用下方的管理指令。当群内公共约定出现冲突时，系统会提示模型按“全局管理员 > 群主 > 群管理员 > 普通成员”的优先级采信；涉及成员个人偏好的信息，则依据本人表达和明确更正来更新。

需要回顾旧事时，直接询问（例如“之前约好的联机几点集合？”）即可。模型会按问题关键词检索当前会话的记忆库，先浏览按相关性排序的标题、摘要与正文节选，再按编号读取完整正文，结果较多时支持继续翻页。由于底层采用字词匹配，若一次未命中，换用更具体的关键词通常就能找到。

## 在群内直接管理

以下指令直接读写记忆数据库，不消耗模型调用。在群聊中，新增、覆写和删除记忆需要群管理员权限，普通群友可执行查询指令；在私聊中由会话本人直接管理。

| 指令 | 用途 |
|---|---|
| `/remember 正文` | 新增条目，成功后返回编号 |
| `/remember --id 42 新正文` | 覆写编号 42 的条目 |
| `/memories [关键词]` | 浏览目录或按关键词搜索 |
| `/memories --page 2 [关键词]` | 查看指定页，每页 10 条 |
| `/memories --id 42` | 查看指定编号的完整正文 |
| `/forget #42` | 精确删除编号 42 |
| `/forget 关键词` | 删除匹配条目并返回删除数量 |
| `/forget_all` | 清空当前会话的长期记忆 |

记忆正文支持纯文本与多段 Markdown，系统会自动从正文中提取标题与简短描述，并保留明确 `@` 提及的群成员身份关联。如果待保存的正文开头恰好带有 `--id` 等形似命令参数的字样，请在最前面加上 `--` 分隔，例如 `/remember -- --id 42 是一个示例`。

即使当前会话关闭了记忆自动注入，上述管理指令依然可用（写入成功时会顺带提示当前未开启自动注入）。删除某条记忆后，后续对话不会再召回该条目；此前已经发给模型的聊天上下文与工具调用记录仍保留在当前会话历史中。

## 在管理页编辑

登录 Web Admin 进入 **“LLM 工坊 → 记忆”**（`/ops/#/memory`），切换“群聊”或“私聊”视图并输入群号或 QQ 号即可查询。页面展示当前会话的已用条数与容量上限，支持按标题、正文、成员名称或 QQ 号搜索并分页浏览。

编辑单条记忆时，可分别修改标题（便于列表定位）、描述（概括核心事实与适用场景）以及完整的 Markdown 正文，也能可视化调整正文中引用的成员身份。点击保存后会直接更新运行数据库并立即生效，无需重新发布 LLM 配置。

每条记忆都会展示其创建或修改渠道（如模型写入、群指令或后台编辑）；若由模型在群聊中写入并关联了触发消息，还会一并记录当时的发言者身份与群内角色，早期历史记录或无消息依据的条目则显示为来源未知。通过后台页面保存的条目会如实标记为管理员后台编辑，保留为空的发言者 QQ 字段。

如果在你编辑期间，模型或另一位管理员恰好更新了同一条记忆，保存时会触发版本冲突拦截；请先刷新列表核对最新内容，再重新修改保存。

## 容量与召回

| 项目 | 默认值 |
|---|---|
| 每个群或私聊的容量 | 1,000 条 |
| 单条正文上限 | 4,096 字符 |
| 标题、描述上限 | 分别为 64、160 字符 |
| 每轮自动召回正文 | 最多 5 条 |
| 本轮记忆输入总预算 | 约 2,048 个估算 token（其中目录最多占 512） |

可在“LLM 配置 → 对话与上下文”中通过 `memory_max_items_per_group` 调整单个群或私聊的存储条数上限，通过 `memory_limit` 调整每轮自动召回的正文条数上限（最高 5 条）；修改后需保存草稿并应用到 Bot，升级版本时会保留你已显式填写的数值。

当记忆条数达到上限时，新增操作会返回已用数量与上限提示，已有条目仍可正常覆写或删除；系统不会自动淘汰旧条目，调低容量上限也不会删除已存数据。

当目录较长或单条正文较长时，每轮自动注入只截取部分目录与最相关的段落，在上下文输入预算吃紧时还会进一步缩减自动附带的篇幅（数据库中的完整正文保持不变）；模型需要核对细节时，可随时通过记忆工具翻页或读取指定编号的全文。

## 升级与备份

从 `v1.16.4` 及更早版本首次升级到 `v1.16.5`（或更高版本）前，请先停止 Bot 和 Web 服务并备份 `data/llm.db`。新版启动时会自动为存量记忆补齐标题、描述与版本号字段，原有的条目编号、正文、时间戳及成员引用均完整保留。

**升级前请注意共享范围变化：旧版群聊中按个人记录的 `scope=user` 条目，升级后会统一转为所在群的共享记忆，同群任意成员触发对话时均可能召回。** 请在升级前先行核对存量数据，清理不适合全群共享的内容。

早期的后台自动抽取功能已退役：配置中的 `auto_memory_enabled`、`auto_memory_prompt`、`auto_memory_max_tokens` 仅做兼容读取而不再执行后台抽取，群内发送 `/llm auto_memory` 会返回迁移说明。同时开启长期记忆与工具调用后，主模型可在对话中通过记忆工具自主维护条目，原自动抽取开关处于关闭状态不会影响这些工具的使用。

长期记忆属于实例本地的运行数据，不纳入 `qqconf`／`qqsync` 的配置同步范围；生产环境与本地开发环境各自维护独立的记忆库，日常备份与恢复请按运行数据库流程操作。
