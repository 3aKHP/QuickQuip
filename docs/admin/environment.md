# 管理环境变量

在 Web Admin“系统 → 环境变量”中管理项目根 `.env`，可新增、覆写、设置空值和删除变量。页面展示变量名与赋值状态，所有已有值均不回显。Provider 编辑页的快捷入口会在新标签页打开对应变量，原有渠道草稿继续保留。

## 修改与保存

1. 搜索已有变量，或输入合法变量名后点击“新增”。
2. 输入完整新值。未编辑的空白输入框保持原值；“设置空值”写入空字符串，“删除”移除该变量的全部同名定义。
3. 点击“预览修改”，核对生效方式、引用渠道和风险说明。
4. 输入管理员当前口令，确认保存。提交成功后输入内容会清空，页面继续显示加载结果。

预览和保存期间出现版本冲突时，刷新状态后重新预览；页面保留本次未提交输入。高危部署和执行环境参数允许修改，预览会说明可能影响。部署位置只影响后续配置工具操作，当前提交固定在当前项目根目录执行。

新值作为字面文本保存，美元符号、引号和换行保留其内容；源码启动和运行时采用相同的 dotenv 解析。已有未加单引号的 `${变量}` 引用按文件中的先后定义展开，单引号内容保持字面值。不要通过浏览器持久存储保存密钥草稿。

## 生效方式

| 修改内容 | 生效方式 |
|---|---|
| 已配置 Provider 的 API Key 与自定义认证 Header 引用 | 运行进程每 5 秒检查一次，新任务使用新凭据 |
| `TIEBA_FORUM_KEYWORD`、`TIEBA_FORUM_KEYWORDS` | 下一次贴吧任务读取配置时使用新关键词 |
| 启动参数、MCP 凭据和未适配变量 | 保存后待人工重启；Docker 环境变量需要重新创建容器 |

轮换凭据不应用未发布的 LLM 草稿。已经开始的 LLM 任务及其重试、工具续轮固定使用开始时的凭据；上游撤销旧密钥后，这些尚未结束的请求可能失败。

引入新渠道时可以先创建变量并保存初始值，再保存、应用 Provider 配置；渠道配置失败时变量仍保留供重试。尚未被渠道引用的变量默认显示待重启，保存渠道引用后会识别其认证用途。

“已保存”表示文件提交完成；加载确认和进程心跳单独显示。停止的服务保持停止，在启动时取得当前凭据。部分进程暂时不可用时，运行进程会自动重试读取；上游连通性通过渠道探活验证，可能按提供商规则计费。

删除正在使用的密钥后，后续新请求报告缺少凭据；不会取回容器启动时的旧值。Trace 保持开发者诊断接口的原始报文契约，详见 [Web Admin](web-admin.md)。

## 各部署方式

源码与 Windows 懒人包直接访问本机根 `.env`。Docker 采用模板中的 `env-agent`，单独挂载部署根目录，通过私有 Unix Socket 分发快照；Bot 只挂载读取通道，Web 另外挂载管理写入通道。agent 不开放网络端口，也不使用 Docker Socket。

已有私有 Compose 需要合入 [生产模板](../../prod.example/docker-compose.yml) 中的 agent、健康依赖、通信卷与环境变量后重新创建服务。未接入 agent 的容器保留原有启动行为，环境管理接口提示不可用。模板更新是首次接入操作，日常凭据轮换不重新创建容器。

环境修改中断时，重新打开环境管理会先恢复文件事务。其他配置写入工具会阻止覆盖未完成的环境事务；请保留 `data/environment/` 下的恢复材料，处理完成后再运行同步工具。

线上改动通过 `qqsync pull` 回流，再运行 `qqconf unpack` 更新工作副本。回流包含私有 `.env` 的实际内容，请按 [配置同步](config-sync.md) 管理。
