# QuickQuip 群内指令速查

QuickQuip 在群里有两类能力：规则回复（复读、接龙、时区猜测、新三国梗、节日问候等）不需要指令，看到合适的消息会自动发生；AI 回复需要你明确触发。本文是命令速查，规则玩法详见各专题文档。

只想用起来的话，先会这几条：

| 想做什么 | 发这条 |
|------|------|
| 问 AI 问题 | `/ai 你的问题`，或直接 @机器人 |
| 查最新资料 | `/search 关键词` |
| 玩个骰子 | `/roll 2d6`，更多游戏见[群内游戏指南](group-games.md) |

---

## 1. 怎么触发 AI

默认两种触发方式：消息以 `/ai` 开头（默认前缀，管理员可修改），或消息里 @机器人，例如 `/ai 你觉得今天适合熬夜吗`、`@机器人 这句话是什么意思`。普通聊天 AI 默认不会乱插话；例外是管理员开启的唤醒模块，会在低频场景下主动搭话（见 §5 唤醒模块）。

触发时支持这些输入形态：

- 文字直接跟在触发词后面；带图时 AI 会一起看，只发 `/ai` 加一张图则按“请描述这张图片”理解。
- 引用一条消息再触发：当前提问和被引用内容会分开理解，不会把被引用的人当成提问者；引用合并转发时，会尽量读取其中的正文和图片。
- 语音消息配合 `/ai` 或 @机器人：语音自动转写成文字进入 AI；协议端自带文本转录时优先使用转录。语音同时计入词云和消息统计。

另外，机器人会在特定传统节日（元旦、春节、元宵、端午、中秋、除夕）自动发送节日问候，日期按公历和农历计算，无需配置。

## 2. 联网搜索

`/search 关键词` 做普通搜索，`/search news 关键词` 搜新闻，`/search finance 关键词` 搜财经。返回最多 5 条结果的摘要和链接，适合查时效性信息；搜得太频繁会提示稍后再试。私聊同样可用。

搜索词越明确结果越准：`/search news OpenAI 最新模型` 通常比只搜 “OpenAI” 更准。

## 3. 玩梗转写

两个独立命令，不依赖 AI 开关是否开启，私聊同样可用。

`/defectify`（别名 `/故障化`）：把输入内容转写成一个读音接近“故障机器人”的五字别名（“故障机器人”即《杀戮尖塔》角色 Defect，与 `/turmfluch` 同属尖塔梗）。输入可以是跟随文字（`/defectify 这人又在群里复读了`）、命令内直接附图、或先引用一条消息再发送（引用里的图片也参与）。输出固定两行：第一行五字结果，第二行 `笑点解析：......。令人忍俊不禁。`

`/turmfluch`：《杀戮尖塔》梗，把输入内容映射到卡牌/遗物词表里语义最接近的名字，只回一句“名字了”（例如“壁垒了”）。输入形态和 `/defectify` 相同，无中文别名；用得太频繁会提示稍后再试。

## 4. 普通成员可用命令

表格里的写法：`<尖括号>` 表示要换成你自己的内容，`[方括号]` 表示可以省略，斜杠分隔（如 on / off）表示任选其一。

### 群与 AI 状态

| 命令 | 说明 |
|------|------|
| `/stats` | 本群消息量与规则触发统计 |
| `/rules` | 本群规则开关一览 |
| `/llm status` | AI 是否开启、当前模型（`/llm` 不带参数同此） |
| `/llm current` | 详细配置：provider / 模型 / 人格、记忆与上下文条数 |
| `/llm health [verbose]` | 各 provider 健康概况，加 `verbose` 看逐项细节 |
| `/llm providers`、`/llm models [provider]` | 列出模型来源与模型（provider 即 AI 服务来源，如 Gemini、OpenAI） |
| `/llm personas` | 列出可用人格 |
| `/llm memory status` | 记忆注入与长期记忆概况 |
| `/llm mcp` | 外部工具（MCP）连接状态 |
| `/memories [关键词]` | 查看本群长期记忆，可按关键词筛选（写入和删除是管理员命令） |

### 语录与留言

| 命令 | 说明 |
|------|------|
| `/quote`（引用消息后发送） | 收藏被引用的消息为本群语录，单条限 500 字 |
| `/quote`、`/quote random` | 随机看一条语录，附编号 |
| `/quote 5`、`/quote #5` | 按编号查看；编号按收藏顺序分配，删除不影响已有编号 |
| `/quote search 关键词`、`/quote s 关键词` | 搜索语录，最多显示 10 条 |
| `/find 关键词` | 搜索最近 30 天群聊记录，最多展示 5 条 |
| `/tell @某人 内容` | 离线留言，对方下次在群里发言时投递；不能给自己留言 |
| `/tells` | 查看等待投递给你的留言 |
| `/untell` | 撤回你发出的最近一条未投递留言 |

### 轻娱乐

| 命令 | 说明 |
|------|------|
| `/roll [NdM]` | 掷骰子，默认 1 个 6 面骰；数量 1-10、面数 2-1000，如 `/roll 2d6`、`/roll d20` |
| `/choose A B C` | 随机选一个，至少 2 个选项；含空格的选项用引号包裹 |
| `/fortune` | 每日运势，同一人同一天结果恒定 |
| `/vote "议题" 选项1 选项2 ...` | 发起投票，议题用引号包裹，最多 9 个选项 |

### 图片、语音与音乐生成

`/draw [模型] [--size 宽x高] [--quality 值] 描述` 生成图片，如 `/draw 一只在喝奶茶的猫`、`/draw openai-dalle3 赛博朋克猫`、`/draw --size 1024x1024 --quality high 未来城市`；引用一张图片再发送 `/draw` 可以以图生图；不带任何参数发送会显示用法和可用模型列表。

`/tts [模型] [--voice 音色ID] 文本` 把文字转成语音；引用一条消息再发送可转写该消息的文本。`/tts models` 列可用模型，`/tts voices [模型] [关键词]` 查音色（如 `/tts voices gemini-tts 温柔`）。

`/music [模型] 风格或主题` 成曲，如 `/music 流行 关于夏天的歌`；不提供歌词时会自动先写词。可用 `--instrumental`（纯音乐）、`--title 标题`、`--lyrics 歌词`；`/music lyrics --title "夏日" 关于夏天和友情的歌` 只写歌词不生成音频，`/music lyrics edit` 在原歌词基础上修改；`/music models` 列可用模型。

三个命令都有频控，过于频繁会提示稍后再试；输入会经过敏感词与提示词过滤。私聊同样可用。

### 贴吧搬运

需要 `tieba_random` 规则开启，仅群聊可用。

| 命令 | 说明 |
|------|------|
| `/tieba [贴吧名]` | 随机发一条缓存帖，带标题、摘要、链接和镇楼图 |
| `/tieba text [贴吧名]` | 同上，纯文字版 |
| `/tieba status [贴吧名]` | 查看缓存与同步状态；`list` 等价于 `status` |
| `/tieba source [贴吧名]` | 查看已配置的来源池摘要 |

### 群内游戏

详见[群内游戏指南](group-games.md)。速查：

| 命令 | 说明 |
|------|------|
| `/game start 数字炸弹` | 猜 1-1000，别名 `bomb`、`number_bomb` |
| `/game start 21点 [赌注]` | 跟庄家比谁更接近 21，别名 `blackjack`、`bj`、`21` |
| `/game start 俄罗斯轮盘 [赌注]` | 1v1 左轮对决，别名 `russian`、`轮盘`、`rr` |
| `/game list / stop / score <游戏名>` | 查看可玩游戏 / 强制结束 / 查看排行 |
| `/sign`（`/签到`）、`/gold`（`/金币`）、`/gold_rank`（`/金币排行`） | 金币系统：签到、查余额、排行 |
| `注册牛牛`、`打胶`、`击剑 @某人`、`我的牛牛` 等 | 牛牛大作战全命令见游戏指南 |

游戏里的冷却时间、保护期、金币消耗都是默认值，可由部署配置调整；打胶和击剑另有群级频控，全群刷屏会被限制。

### 人物志

`/profile [short|middle|long|full] @某人` 用 AI 给群友写人物志，模式词在命令任意位置都行（如 `/profile @某人 long`）。`short` 接近旧版短评，`middle` 是默认，`long` 用更多发言样本，`full` 尽量读取该群已记录的完整发言；长文以合并转发形式发送。需要 AI 可用，仅群聊。

## 5. 管理员可用命令

以下命令需要群管理员或群主身份。管理员指 OneBot 协议里的群管理角色，与机器人部署者无关。

### AI 开关与配置

| 命令 | 说明 |
|------|------|
| `/llm on` / `/llm off` | 开关本群 AI |
| `/llm use <provider> [model]` | 切换模型；名称用 `/llm providers`、`/llm models` 查 |
| `/llm persona use <人格ID>` | 切换人格；用 `/llm personas` 查 |
| `/llm trigger prefix <前缀>` | 修改触发前缀（默认 `/ai`） |
| `/llm trigger prefix_mode on / off` | 开关前缀触发 |
| `/llm trigger at on / off` | 开关艾特触发（仅群聊有此命令） |
| `/llm memory on / off` | 开关记忆注入 |
| `/llm auto_memory on / off / reset / status` | 自动记忆抽取的开关、跟随全局默认、查看 |
| `/llm context_limit <条数>`（`reset` 或 `off` 恢复默认） | 设置本群上下文读取条数，群聊最高 20 条（全局默认 10）；重启和 `/llm clear_context` 不影响此设置 |
| `/llm clear_context` | 清空本群短期上下文，AI“串台”或记错上下文时用 |
| `/llm delete_msg` | 引用一条消息发送本命令，或 `/llm delete_msg <消息ID>`，从上下文删除该条 |
| `/llm reload` | 重载 LLM 配置并重置本群上下文条数覆盖；作用于整个部署，重载后的探活会发一条真实请求，可能产生计费 |
| `/llm probe` | 并发探活所有 provider，逐个汇报可用性 |
| `/llm mcp reload` | 拉取 MCP 镜像并重连，完成后返回连接状态 |

私聊中这些改动类命令任何人可用（无管理员判定），详见[私聊指令速查](private-commands.md)。

### 记忆管理

| 命令 | 说明 |
|------|------|
| `/remember 内容` | 写入本群长期记忆 |
| `/forget 关键词` | 删除所有匹配的记忆 |
| `/forget_all` | 清空本群全部长期记忆 |

查看记忆（`/memories`）普通成员即可用，见 §4。

### 规则开关

`/disable <规则名>` 禁用一条规则，`/enable <规则名>` 重新启用；规则名用 `/rules` 查看。设置会持久化，重启不丢。

### 唤醒模块

唤醒模块决定 AI 会不会主动搭话。查看状态用 `/awakening status`（别名 状态），开关单条规则用 `/awakening on / off <规则名>`（别名 开启 / 关闭 / 禁用 / 启用）：

| 规则名 | 说明 |
|------|------|
| `awakening_extend` | 显式触发 AI 后的一小段时间内，继续回应同一用户 |
| `awakening_interest` | 命中配置的兴趣话题时回应 |
| `awakening_relevance` | 判断群友是否在延续 bot 刚才的话题 |
| `awakening_qa` | 判断群友是否提出了需要回答的问题 |
| `awakening_boredom` | 群聊沉寂达到配置时长后主动冒泡 |
| `awakening_fallback` | 按低概率兜底触发 |

行为要点：只有 `awakening_extend` 会承接你刚刚明确艾特或前缀召唤后的后续对话，其余唤醒不会让 bot 持续接普通聊天；兴趣、相关性、答疑、延长和无聊唤醒触发时会携带群内最近发过的少量历史图片，显式触发和兜底唤醒不带。无聊唤醒默认关闭，需要本群单独开启：`/awakening boredom on / off`。具体阈值和兴趣话题由部署者在 `config/awakening.toml` 配置。

### 每日播报与总结

播报（早/午/晚报）和总结（日报/周报/月报）默认关闭，开启需要管理员执行命令，且部署者需在 `config/llm.toml` 全局启用对应功能。生成与发布时刻由部署配置的定时任务决定。立即生成类命令每分钟限一次。

| 命令 | 说明 |
|------|------|
| `/briefing on / off / status`（别名 开启 / 关闭 / 状态） | 开关本群早/午/晚报动态简报 |
| `/briefing now [morning / noon / evening]`（别名 立即 / 测试） | 立即生成一期，默认生成当前时段对应的版式 |
| `/summary on / off / status` | 开关本群每日总结（约 2000 字小作文风格日报） |
| `/summary now` | 立即生成从上一个固定时点到当前时刻的总结，直接发群，不存档 |
| `/summary weekly / monthly on / off / status`（别名 周报 / 月报） | 开关群周报 / 群月报，与日报相互独立 |
| `/summary weekly / monthly now` | 立即生成上一个完整周期（上周 / 上月）的回顾 |

周报、月报与日报的差异：时间跨度更长；因消息量大按天均匀采样（周报每天约 50 条、月报每天约 20 条）喂给 AI，控制成本的同时覆盖全周期。播报生成中若当前模型输出异常中断，会自动改用级联里的下一个播报模型，不会发出半截简报。

### 定时消息

定时消息是"到点自动向群里发内容"的任务，由管理员用命令管理，也可以在 Web Admin 的「定时消息」页面维护。任务持久化保存，重启不丢。cron 为 5 段式（分 时 日 月 周），按服务器本地时间触发；注意周字段 0=周一、6=周日，不支持用 7 表示周日。

| 命令 | 说明 |
|------|------|
| `/schedule list`（别名 `/定时`） | 列出本群的定时消息任务 |
| `/schedule add <cron> <消息>` | 新增固定文案任务，如 `/schedule add 0 7 * * * 早上好！` |
| `/schedule add llm <cron> <任务指令>` | 新增 LLM 任务：到点把任务指令交给 AI，结合群聊动态生成内容发出 |
| `/schedule add once <cron> <消息>` | 一次性任务（触发一次后自动删除），`llm` 与 `once` 可组合 |
| `/schedule on / off <任务ID>` | 启用 / 停用任务 |
| `/schedule del <任务ID>` | 删除任务 |

普通群友也可以直接对 bot 说"今晚七点提醒我看 KPL"之类的话，AI 会自行创建一次性的 LLM 定时任务（需要部署者在 `config/llm.toml` 的 `[tools] enabled` 中启用 `manage_scheduled_messages`）。LLM 类任务受规则开关 `scheduled_message_llm` 控制（`/disable` / `/enable`），且需要本群 LLM 处于启用状态。

### 统计、词云与热重载

| 命令 | 说明 |
|------|------|
| `/reset_stats` | 重置并保存本群统计 |
| `/wordcloud [today / week / month / year]`（别名 `词云`） | 生成本群词云图，默认当天 |
| `/reload_rules` | 重新加载聊天规则（`chat_rules.toml`），在线改完配置文件后立即生效 |
| `/reload_personas` | 重新加载 LLM 人格（`personas/` 目录） |

`/reload_rules` 和 `/reload_personas` 常用于通过 Web Admin 在线编辑配置文件之后让改动立即生效。

### 贴吧管理

| 命令 | 说明 |
|------|------|
| `/tieba refresh [贴吧名 / all]` | 强制同步缓存，默认全部来源 |
| `/tieba_peek <贴吧名>` | 绕过缓存，从指定贴吧现爬一条随机帖 |

如果 `refresh` 提示需要人工续签登录态，在机器人所在机器上运行 `python -m quickquip.tieba.login` 重新登录。

## 6. 记忆与隐私

AI 的“记忆”分两层：短期上下文是最近几轮对话，可用 `/llm clear_context` 清掉；长期记忆是手动 `/remember` 存入的内容，用 `/memories` 查看、`/forget` 删除。

AI 不会把全天群聊偷偷记下来，只有显式触发 AI 时才会用到有限的上下文。

## 7. 常见问题

**发了消息 AI 不理我？** AI 只在 `/ai` 前缀（或管理员改过的前缀）和 @机器人时回复，普通聊天不会触发；确认本群 AI 已开启可看 `/llm status`。

**AI 没记住我手动加的记忆？** 先 `/llm memory status` 看“记忆注入”是否开启，再 `/memories` 确认记忆确实存进去了。

**AI 回得很怪？** `/llm current` 检查当前模型是否是想要的那个；怀疑上下文串了就让管理员执行 `/llm clear_context`，个别消息的问题可用 `/llm delete_msg` 定点移除。
