# AI 工具发现说明

QuickQuip 的 AI 在回答前，可能先查找可用的工具再作答。本文说明这一机制的原理和对使用的影响。

---

## 1. 什么是工具

QuickQuip 的 AI 回复不只会聊天，也能在需要时调用工具，例如：

- 查群友身份和别名
- 查已保存的长期记忆
- 联网搜索
- 查看群状态
- 画一张矢量图（梗图、图表等，管理员开启后可用）
- 调用管理员接入的外部 MCP 能力

普通闲聊不一定会用工具。只有当问题确实需要外部信息或群内资料时，AI 才会尝试调用。

---

## 2. 为什么会出现“先找工具”

如果管理员接入了很多外部工具，机器人不会把所有工具说明都塞进每次 AI 请求，以减少无关信息、让模型更专注当前问题。这时 AI 可能先调用 `tool_search` 查找合适的工具，再用找到的工具完成回答；如果它认为工具存在但搜索没有命中，也可能调用 `tool_list` 查看工具组或工具名，再加载具体工具。这个过程不需要你额外操作，只是回复可能多等一轮。

---

## 3. 怎么提问更容易命中工具

直接说清想要的能力，例如 `/ai 帮我查一下这个 GitHub 仓库最近有哪些 PR`、`/ai 搜一下最近关于某个版本的公告`、`/ai 查查群里有没有关于阿桃喜欢什么的记忆`。知道管理员接入了哪类外部工具时，可以把工具来源说出来，如 `/ai 用 GitHub 工具查一下这个项目的 issue`。

---

## 4. 常见情况

**提示没有找到工具**：通常是当前机器人没有启用对应能力，或者描述太模糊。换个更具体的说法，例如把“查一下那个东西”改成“用 GitHub 查仓库 issue”；知道工具来源时也可以说“列一下 GitHub 工具再找 PR 相关的那个”，机器人会更容易走 `tool_list` 兜底。

**提示工具结果不足**：工具被找到了，但返回的信息不够完整；AI 不会在结果不足时强行编造。

**普通聊天不受影响**：工具发现只作用于需要工具的 AI 回复，复读、彩蛋、接龙等规则功能与其无关。
