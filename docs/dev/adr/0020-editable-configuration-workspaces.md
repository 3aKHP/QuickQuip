# ADR-0020：以持久 TOML 工作副本编辑配置包

- 记录日期：2026-10-24
- 原始决策日期：2026-10-24

后续决定见 [ADR-0022：以 qqconf 统一编辑本地持久化配置](0022-local-configuration-workspace-cli.md)。

## 背景

LLM 配置迁入 SQLite（[ADR-0001](0001-config-snapshot-publication.md)）并建立三方同步基线（[ADR-0019](0019-configuration-three-way-sync.md)）后，管理员可以通过 Web Admin 在线修改配置，但也经常需要在本地集中审阅多渠道配置，或委托编码代理批量调整参数与人格文件。直接导出单份大体积 JSON 既不便于按模块拆分阅读，也无法编写注释；若每次都从数据库重新导出覆盖本地目录，又会冲掉人工补充的注释和尚未提交的半成品修改。

## 决定

在统一配置包之上提供持久化的版本化 TOML 工作副本，由本地 CLI 负责初始化、语法与引用校验、变更计划预览、草稿组装、基线刷新及中断恢复：

- 工作副本在本地目录中同时维护可编辑的拆分 TOML 文本与隐藏的同步基线。执行组装时，工具将工作副本转换为 SQLite 中的新版 LLM 配置草稿并更新受管文件资产；后续将草稿发布给 Bot 或同步至远端服务器，继续复用既有的快照发布与服务器同步流程。
- 空值、超出有符号 64 位范围的大整数以及含保留键的对象采用无歧义的可逆 TOML 编码。工作副本通过清单文件记录拆分对象的集合与排列顺序，非 LLM 文本资产按原始字节保留。三方合并的冲突检测粒度保持为整份 LLM 配置文档与单个独立文件资产。

## 方案与理由

一次性导入导出只能解决“把数据库转成文本改完再塞回去”的单次需求，持久工作副本则能借助本地基线在数据库刷新后保留行内注释与尚未组装的本地改动。由 SQLite 负责配置结构与跨对象引用校验、由工作副本负责拆分布局与注释保真，可以让存储语义和人类可读性各司其职。

首版工作副本沿用 [ADR-0019](0019-configuration-three-way-sync.md) 已验证的“整份 LLM 文档 + 单个文件资产”冲突粒度，以便直接复用当时的引用完整性与有序列表校验，将字段级细粒度三方合并留待后续迭代。组装写入复用端点配置事务，并通过持久化操作日志与恢复副本兜底跨文件与数据库的写入中断，防止半途失败留下不一致状态。

## 影响

项目新增 `tomlkit` 依赖以保留 TOML 注释与排版，并引入受版本约束的工作副本目录格式。向真实配置目录安装文件资产前须先停止正在读取配置的进程，且新写入的人格或模板资产必须兼容当前已发布的配置快照，确保服务能够正常启动。若工作副本外部的真实配置在预览后发生变动，原先生成的组装计划即告失效，恢复流程也会拒绝直接覆盖外部新改动，交由管理员显式核对。
