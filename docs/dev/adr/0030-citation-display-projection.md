# ADR-0030：独立生成来源引用的显示投影

- 记录日期：2026-11-16
- 原始决策日期：2026-11-16

## 背景

联网搜索生成的回答常带有密集的行内来源链接与模型自动追加的参考尾块，直接原样发到 QQ 群聊或私聊窗口会大幅挤占版面、打断阅读节奏；然而完整的模型响应正文与协议原生块仍需承担跨轮历史回放、前缀缓存复用以及事后来源核查，且消息交付记录保存的原文字符区间还用于定位和撤回单条已发送消息。

## 决定

将持久化模型正文与面向聊天出口的显示文本解耦，在交付层独立生成来源引用显示投影：

- **保留完整原文、投影隐藏引用**：存储层完整保存规范化响应正文与协议原生块；交付层基于协议返回的结构化引用注解与明确的引用标记语法生成独立的显示文本，自动剥离已确认的来源引用链接与自动来源尾块，同时原样保留用户操作入口、文件下载链接以及代码块内的示例 URL。
- **显示态切分与原文坐标回映**：长回复的分段切分在净化后的显示文本上按可见字符预算执行，切分完成后将每一段的起止边界精确映射回原始正文坐标，并一并冻结每段实际发出的显示文本。版本化的来源元数据与冻结显示片段随对应的 Turn 和交付记录在同一数据库事务内原子落库；显示投影字段仅供聊天发送与消息撤回使用，不进入跨轮模型历史与纪元冻结前缀。

## 方案与理由

- 若在落库前直接删改模型正文中的引用标记，不仅会破坏原生回放与纪元前缀的一致性，还会导致事后排障时无法追溯回答所依据的网页来源。
- 若先把完整原文切分成多条待发片段、再在每段发送前单独用正则剔除 URL，跨段折行的引用语法容易匹配残缺，且交付表记录的原文偏移量会与用户实际看到的文本失配。
- 在完整 Turn 粒度上先行生成显示投影并维护双向偏移映射，能够同时满足可见字符分段预算、单段精准撤回、聊天界面清爽度以及后台来源可追溯四项要求。

## 影响

`llm.db` 增量存储版本化的来源引用元数据与冻结的显示文本片段，带来少量可控的存储体积增长；升级前的历史交付记录无显示投影字段，继续按原有的原文字符区间读取和解释。后续若需调整聊天端的引用呈现样式（如切换隐藏或摘要形态），可直接演进同一交付投影入口，且策略变更仅作用于新生成的交付计划，不改写既有记录。
