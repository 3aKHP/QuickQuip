# ADR-0011：以事务部署版本并保留共享运行数据

- 记录日期：2026-10-23
- 原始决策日期：未确认；v4 部署实现于 2026-09-08 经 PR #226 合并

## 背景

直接覆盖运行目录会混合上传、构建、配置替换和重启。并发操作、构建失败或连接中断时，很难确定哪些文件和容器已经改变；代码回退也可能意外恢复旧凭据或运行数据。

部署需要可识别的候选版本、明确的激活时点，以及能够核对结果的恢复过程。

## 决定

每次操作使用独立上传区和操作标识。候选版本先完成编排校验与镜像构建，修改线上文件和激活版本时持有服务器部署锁。运行入口通过版本目录及 current、previous 链接管理。

激活前备份本次会替换的共享文件，健康检查失败后恢复原文件、链接和容器并再次验证。远程事务独立于客户端连接运行，操作日志保留最终结果。

应用凭据与数据库使用共享来源。人工代码回滚保留当前凭据和运行数据，数据库迁移兼容性通过升级与恢复流程单独处理。

## 方案与理由

旧平铺目录和直接覆盖驱动缺少候选构建与线上修改之间的明确边界。版本目录、隔离上传和持锁激活使部署失败能够归属到具体阶段，保留上一版本的文件与本地镜像也使恢复输入可确定。

自动恢复撤销本次共享文件变更；人工回滚选择旧代码并保留当前共享数据。这两种操作面对的目标状态不同，因此分别维护恢复规则。

## 影响

构建失败可以在激活前停止，激活失败有可核实的恢复路径。自动恢复成功时，原部署仍报告失败；恢复失败保留证据并单独报告。

维护者需要管理保留版本、镜像、配置写入的原子性及数据库兼容。后续接入的共享 Skill 目录按可变部署资产维护，代码回滚继续沿用相应共享目录契约。
