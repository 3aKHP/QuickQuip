# ADR-0018：将 MCP 结果归一化为受控内部内容

- 记录日期：2026-10-23
- 原始决策日期：2026-08-08；文本资源交付于 2026-09-11 扩展

## 背景

MCP 工具可以返回文字、图片、资源及其他内容。将未知结果原样转成 JSON 文本，会让 base64、资源标识和未支持内容进入日志或模型请求；不同 provider 也需要各自的多模态格式。

工具链需要统一的内部结果，以及每种内容进入模型前的校验和省略规则。

## 决定

MCP 层先将外部结果归一化为受控的内部类型，再交给共用工具链。可见文本按既有规则组合；未支持或无效的内容提供有限诊断。provider 适配器消费内部内容，并完成自己的协议序列化。

图片严格解码并校验格式、大小和 MIME，验证后的字节在当前工具循环中使用。视觉模型接收支持的图片表达，非视觉模型使用已配置的转述能力；工具错误、内容拦截或转述失败按相应规则省略图片。

## 方案与理由

将未知结果原样序列化为 JSON 文本虽然能兜底展示返回内容，但会绕过针对各内容类型的体积限制、安全检查与多模态交付约束。先建立受控的内部归一化边界，再按需逐类扩展支持范围，能够让外部 MCP 协议结构与不同模型的输入能力在统一工具链内可靠衔接。

2026-09-11 的扩展允许内联文本资源按文本 MIME 白名单与字符长度上限进入工具文本管线；二进制 `blob`、音频与外部资源链接仍予以省略并返回结构化诊断提示，资源 URI 既不触发客户端自动下载，也不随内联正文直接拼入模型上下文。

## 影响

新增支持的 MCP 内容类型必须显式定义格式校验、体积预算、错误降级与多模态交付行为，不得通过未知内容兜底分支隐式放行。归一化后的图片仅供当前工具循环内的模型推理消费，向 QQ 聊天窗口发送媒体文件由专门的业务发送工具独立承担。

`llm.db` 业务执行记录按工具结果保留策略（[ADR-0005](0005-tool-result-retention.md)）裁剪保存归一化内容；原始 HTTP Trace 作为独立的排障诊断留档，在开启开关时可能记录实际发往上游的多模态请求报文。
