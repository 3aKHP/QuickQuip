# ADR-0004：分离执行记录、历史投影与消息交付

- 记录日期：2026-10-23
- 原始决策日期：2026-09-05

## 背景

一次工具调用交互会产生多个模型响应，每个响应可以包含正文和工具声明。正文又可能拆成多条 QQ 消息，发送过程还可能出现部分成功、失败或回执未知。仅保存最终回复，或按成功发送片段恢复模型历史，都会丢失生成过程及其边界。

## 决定

执行记录保存已提交的模型响应、工具调用与执行状态；历史投影按目标协议与预算生成请求表达；交付记录保存计划发送的内容、实际尝试和回执。三者通过稳定 ID 关联。

一次外部触发建立 Agent Loop，每个完整模型响应形成 Turn，同一 Turn 的正文可以划分为多个 Chunk。交付还可包含工具媒体和主机通知。持久化先提交 Turn、工具声明和交付计划，再启动相应外部操作。

## 方案与理由

沿用仅保存末轮正文的历史入口，无法覆盖工具过程中的普通正文。把已发送片段直接作为模型历史，又会让平台拆分参数改变模型轮次和重放内容。因此，已确认方案分别保留生成事实、投影表达和交付结果。

结果未知的发送保留独立状态，并终止当前 Loop 后续工作。恢复按已记录事实收束；工具和消息的重复执行需要独立的幂等依据。

## 影响

模型正文能够追溯到 Turn 和交付记录；修改拆分参数时，模型轮次与工具配对保持自己的语义。引用、撤回、取消与历史回放可以沿关联 ID 处理。

实现需要维护跨表事务、generation 校验、交付状态和异常收尾。模型生成成功、工具完成和确认送达分别记录，回执未知的后续处理也需要保留明确语义。
