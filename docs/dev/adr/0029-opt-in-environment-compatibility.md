# ADR-0029：显式启用环境管理并保留部署兼容性

- 记录日期：2026-11-09
- 原始决策日期：2026-11-09
- 替代：[ADR-0028](0028-write-only-environment-management.md)

## 背景

QuickQuip 同时支持源码直跑、Windows 懒人包以及由部署者自行维护私有 `docker-compose.yml` 的容器部署。[ADR-0028](0028-write-only-environment-management.md) 引入后台环境变量只写管理与运行时凭据快照后，若在升级后默认强依赖 `env-agent` 或无条件接管进程环境，既有未配置新组件的私有编排便会在启动阶段报错。此外，宿主机或容器编排直接注入的外部环境变量、后台写入的受管字面值以及显式删除某个变量的操作之间需要定义清晰的叠加优先级，且字面值转义与删除意图必须在 `qqconf` 和 `qqsync` 跨环境同步时无损保留。

## 决定

在保留 [ADR-0028](0028-write-only-environment-management.md) 只写接口、口令二次确认、乐观锁版本检查、可恢复文件事务以及 `env-agent` 双私有 Socket 隔离模型的基础上，将环境变量管理调整为显式启用的可选能力，并补齐外部注入与同步合并规则：

- **默认关闭与显式开关**：通过环境变量 `QUICKQUIP_ENV_MANAGEMENT_ENABLED` 控制是否启用环境管理，默认值为关闭，并在进程启动时锁定。关闭状态下，Bot 与 Web 直接沿用传统进程启动环境，跳过 `env-agent` 连接与快照轮询，也不初始化环境管理状态；此时若容器编排仍启动了 `env-agent`，该服务继续监听私有 Socket 以满足容器健康检查依赖，但对所有请求固定返回 `disabled` 且完全不触碰底层 `.env` 文件。仓库分发的公开 Docker 模板在 `env-agent`、Bot 与 Web 三个服务上显式开启该开关，已有私有 Compose 则可在未改造前无缝保持关闭。Web Admin 通过公开能力元信息展示当前启用条件与后端就绪状态，关闭时直接拒绝写入请求。
- **字面值保护与 dotenv 解析兼容**：未携带受管标记的普通 `.env` 条目继续交由 `python-dotenv` 解析，维持“进程启动加载时外部注入环境优先、配置工具离线解析时文件定义优先”的既有规则；带有 `# quickquip:literal` 受管标记的条目在解析阶段先替换为安全占位符以屏蔽 `$` 变量插值，待跨变量依赖展开完毕后再还原为原始字面值，同时兼容读取旧版已保存格式。
- **运行期环境叠加与删除墓碑**：开启环境管理的进程以启动时的有效环境变量集合为基线，在其上叠加受管字面值覆盖与显式删除操作——写入空字符串会覆盖同名外部注入值，而 `.env` 文件中单纯不存在某变量并不会抹除宿主机或 Compose 注入的同名变量。当管理员在后台删除某个变量时，存储层移除文件中全部同名定义并写入 `# quickquip:deleted NAME` 墓碑注释；后续重新定义同名变量时自动移除该墓碑。墓碑注释随 `.env` 文件参与 `qqconf` 与 `qqsync` 按变量名进行的三方合并；若候选文件中同时出现同名变量定义与删除墓碑则直接报错拒绝，要求显式消解。关闭环境管理时，墓碑注释仅被视作普通文本注释。
- **启动期历史删除补齐**：进程在开启环境管理并首次加载时，若检查本地环境事务日志发现最后一次已提交操作为删除某变量、且当前 `.env` 文件中确实不存在同名定义，则通过同一原子文件事务自动补写对应的 `# quickquip:deleted` 墓碑；若该变量此后已被人工恢复定义或重新创建，则保留当前文件内容不变。每次 LLM 任务仍在启动时固定当次凭据快照，HTTP Trace 继续按独立诊断开关留存原始报文。

## 方案与理由

如果仅凭检测到根 `.env` 文件或 Socket 路径存在就自动激活环境管理，既有部署在常规代码升级后便会意外改变凭据读取路径；改为显式开关后，“升级应用版本”与“改造容器编排以接入在线凭据轮换”成为两步可独立安排的运维操作。由于运行期动态切换该开关会同时改变凭据权威来源与后台轮询生命周期，开关状态固定在进程启动时读取，变更后通过重启切换。

在容器与系统服务部署中，不少非涉密运行参数由外部编排直接注入进程环境而非写在 `.env` 里；若直接用 `.env` 全量替换运行时环境，会导致外部注入项丢失。采用“启动环境基线 + 受管覆盖与墓碑叠加”模型，既保留了外部编排注入能力，也解决了“文件里没写某变量究竟是未纳管还是已被管理员删除”的歧义，并让删除操作能够跨环境可靠同步。

## 影响

Docker 部署首次启用在线环境管理时需同步更新 Compose 编排并重建相关容器，启用后的日常渠道凭据轮换即可直接通过内存快照热刷新完成。若显式开启了开关但后端存储或 `env-agent` 不可用，进程在启动阶段即快速失败报错；运行期间若通信短暂异常，进程保留最后一次确认成功的凭据快照并持续后台重试。管理员若计划从启用状态改回关闭状态，需先核对 Compose 或宿主机环境中是否仍残留早先注入的旧凭据，避免关闭覆盖层后旧环境变量重新暴露生效。
