# ADR-0017：保留可选 Skill 副本并显式检测和同步漂移

- 记录日期：2026-10-23
- 原始决策日期：2026-09-22

## 背景

预置 Skill 随项目版本分发，部署者将副本安装到运行目录。应用升级后，已安装副本可能继续使用旧文档和脚本；直接覆盖又可能丢失部署者的定制。

self-docs 尤其依赖与应用版本相符的资料，因此需要让陈旧或已修改的副本可辨认、可更新。

## 决定

保持单一、平等、可选的 Skill 目录模型，官方预置内容以可安装模板分发。运行时比较已安装副本与当前预置基准的目录指纹，通过日志和只读状态展示漂移。

同步由部署者显式执行。命令行与管理后台使用共同的状态与同步语义，安装缺失项或覆盖分叉项前按规则处理冲突并保留备份。对话侧能力提供只读使用和状态查询。

## 方案与理由

早期评估推荐引入包内只读的内置层，再由本地副本覆盖。维护者最终选择保留既有分发模型，将本轮问题收敛到漂移可见性和可控同步，避免同时引入运行时优先级与额外层级。

讨论也评估过由 updater Skill 在聊天中执行更新。同步会改写部署者资产，而对话触发面与容器挂载权限不适合承担这项管理职责，因此写入落在部署者工具和已鉴权管理面。

## 影响

部署者保有安装、定制与更新选择权，预置内容在运行时按普通 Skill 使用。文件指纹能够报告差异，差异是否为有意定制需要由维护者判断。

更新覆盖分叉项时保留原副本，部署合入新增内容时保留已有文件。self-docs 的源文档同步与部署端已安装副本同步分别维护，升级应用后需检查后者的漂移状态。
