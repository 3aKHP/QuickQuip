# ADR-0022：以 qqconf 统一编辑本地持久化配置

- 记录日期：2026-10-26
- 原始决策日期：2026-10-26

后续决定见 [ADR-0024：工作副本与单向配置部署](0024-directional-configuration-deployment.md)。

## 背景

配置与运行数据分离后，可编辑配置分布在配置库、TOML、JSON、YAML 和根 `.env`。维护者需要在一个工作副本中完成日常编辑，真实 `config/` 和 `data/` 主要承担机器读写。此前的清单、操作编号和手工确认摘要增加了日常操作负担，整文档冲突也妨碍独立字段合并。

## 决定

本地工具命名 `qqconf`，提供 `unpack`、只读 `refresh` 和 `pack`。默认工作副本为忽略的 `.config-workspace/`；数据库逻辑内容展开为 `db/` 下的业务 TOML，普通文本保留原格式和相对路径。目录自动发现对象，稳定身份写在正文，基线由工具维护。

使用共同基线、工作副本和真实来源进行字段级三方合并。默认冲突停止整次写入，显式来源偏好只处理冲突字段。写回校验完整目标，LLM 保存草稿，配置应用由部署流程负责。

Bot 和 Web 均确认停止时写真实配置；任一运行或状态未知时生成完整 `.config-staging/` 候选。服务生命周期锁与离线写入共享。跨文件写入保留持久日志，后续写命令自动恢复，预览保持只读。

服务器同步与部署工具以真实配置和候选为桥梁，独立于工作副本。项目内的凭据、作用域覆盖、循环定义和标准运维配置纳入本地管理；Skill 资产、LLBot 混合状态、Trace 当前开关和运行数据继续由各自入口维护。

## 方案与理由

继续逐文件登记会要求维护者同步编辑正文与清单；按目录发现更贴近日常新建人格和供应商的习惯。稳定身份承担合并匹配，顺序文件只表达排序。

整文档覆盖容易丢失另一侧的独立修改。字段合并保留独立编辑，并对顺序敏感的级联和普通数组保留整体选择。预览与执行重新读取实际内容，用户无需管理校验摘要。

直接写运行中的应用文件会混合“编辑”和“生效”。自动生成候选让工作副本编辑独立于服务运行；第二个 CLI 可以统一处理本地和远程部署。

## 影响

旧工作副本保留作备份，通过新目录重新展开接入。工具增加配置清单和独立恢复事务，须持续验证文本保真、秘密预览、服务状态以及中断恢复。真实配置存储与业务数据库保持 [ADR-0021](0021-configuration-runtime-storage-separation.md) 的归属。
