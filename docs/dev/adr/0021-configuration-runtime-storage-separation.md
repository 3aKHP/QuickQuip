# ADR-0021：先分离配置与运行数据，再重构本地配置工具

- 记录日期：2026-10-26
- 原始决策日期：2026-10-26

## 背景

配置工作副本需要覆盖项目的持久化配置，包括 LLM 配置、群级覆盖、独立配置文件和根 `.env`。配置与运行数据目前共用部分 SQLite 数据库：

| 存储 | 配置内容 | 同库的业务或运行内容 |
|---|---|---|
| `data/llm.db` | `group_settings` 中的模型、人格、触发方式等覆盖项 | 对话、记忆、会话、纪元和 Agent 执行记录 |
| `data/niuniu.db` | `niuniu_group_text` 中的群级文案模式 | 玩家状态与游戏操作记录 |
| `data/llm_config.db` | 配置文档、关系投影、修订和不可变快照 | `config_operations` 中的应用与探测任务、`bot_runtime` 中的加载状态和心跳 |

表名也不足以确定数据归属。`group_settings` 同时接受群和私聊作用域；私聊会话的开始、结束和恢复会在业务事务中更新其中的 `enabled`。拆分这张表需要核对字段语义及其事务依赖。

配置导入、暂存、同步和部署需要保留目标环境正在增长的业务记录、任务和心跳。若由配置工具长期负责业务库中的定点读写，工具将持续依赖各业务库的表结构和事务规则。

## 决定

将配置与运行数据的存储解耦作为本地配置工具重构的前置工作，采用统一配置库与独立运行存储，停服迁移后再实现新的工作副本 CLI。

1. 按数据的用途和写入所有者核对全部持久化存储。配置描述管理员希望系统采用的参数；业务与运行数据记录已经发生或正在进行的活动。配置修订、快照、发布指针等配置生命周期数据单独说明归属。
2. 将业务库中的配置提取到独立的配置存储，并为配置提供明确的读写入口。现有配置库中的运行任务与心跳也纳入解耦设计。配置库使用 `config/managed/config.db`，执行任务和发布指针使用 `data/config_runtime.db`。
3. 保留业务生命周期与执行记录的完整性。涉及配置引用、会话开关及发布确认的跨存储协作，由应用领域负责定义一致性；配置 CLI 面向解耦后的配置入口工作。
4. 本地工作副本工具负责配置导出、预览和写回；配置同步与部署工具连接本地及目标环境的真实配置。两者通过真实配置衔接，工作副本由本地工具独立维护。
5. 现有 TOML、YAML、JSON 和 dotenv 继续保持其格式。将剩余文本配置统一迁入 SQLite 的议题单独跟踪。

循环任务定义保留 JSON，位于共享配置目录；一次性待办保存在运行数据目录。群设置与文案模式保持现有生效方式，私聊启停归入会话运行状态。配置交换只搬运内容，本机历史和运行记录各自保留。

## 方案与理由

### 在配置工具中管理业务库的配置子集

按表和字段读取配置，写回时合并目标业务库，可以沿用现有布局。每增加一个混杂库，配置工具就需要适配该库的 schema、写入锁、暂存和恢复规则；业务流程还可能在同一事务中更新这些字段。

### 先解耦存储，再实现配置工具

配置拥有独立的存储和应用入口后，工作副本、同步与部署可以共享这一边界。业务数据继续由各自领域维护，配置工具的输入和写回目标更稳定。

该路径需要先调整业务读取、写入和迁移流程，尤其要处理私聊会话开关及配置发布的一致性。采用先解决这些存储职责的顺序，再扩展配置工具。

## 影响

实现遵循以下约束：

- 为表、字段和作用域标明配置、业务数据、运行状态或配置生命周期数据的归属。
- 定义配置引用的校验、草稿与已发布来源，以及服务加载配置的方式。
- 保留私聊会话开始、结束、恢复和在途执行的现有语义。
- 保留任务绑定不可变快照、发布指针更新和 Bot 加载确认之间的一致性。
- 为已有安装设计迁移、兼容期、失败恢复和回退，明确迁移后的写入所有者。
- 验收配置修改和同步时，持续产生的业务记录、任务状态与心跳保持完整。

## 落地核对

统一配置、运行控制、业务会话和定时消息通过各自入口维护。迁移使用停服备份和记录校验；迁移完成后的回退反向转换存储并保留新增业务记录、配置及任务进度。具体契约见[配置与运行存储](../configuration-storage.md)，操作见[存储迁移](../../admin/storage-migration.md)。

工作副本 CLI 继续采用 [ADR-0020](0020-editable-configuration-workspaces.md) 的现行契约，新交互与扩大受管范围在后续工具重设计中实现。
