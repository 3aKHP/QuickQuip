# ADR-0012：将动态轮次信息放入当轮信封

- 记录日期：2026-10-23
- 原始决策日期：2026-09-03；方案于 2026-09-04 完成评审定稿

## 背景

模型请求的 system prompt 曾包含时间、参与者、记忆和词表命中。这些内容随每轮变化，使稳定的人格与行为要求也无法形成可持续复用的请求前缀；日期变化还会改变跨日请求。

机器人仍需要知道当前时间和现场资料，需要为稳定指令与本轮信息分别安排位置。

## 决定

system prompt 保留人格、风格、消息解释与工具使用规则等稳定内容。时间、节日、参与者、相关记忆及词表命中在组装请求时放入当前 user 消息头部的“轮次上下文”信封。

信封按当前请求渲染，随该次 Agent Loop 使用，作为请求材料管理。历史持久化与重放使用允许保留的规范内容；现场补丁、图片及历史窗口分别按各自生命周期处理。

## 方案与理由

保留动态 system 内容会让时间和资料变化持续改写请求头部。将其移到当前轮次末端，可以同时表达稳定要求和最新事实，并为支持前缀缓存的渠道提供稳定输入。

当时也评估过显式缓存及逐字请求重放，实施选择先处理提示词内容归属，并与纪元窗口和预算配合。渠道是否命中缓存仍取决于其协议、模型和实际请求形态。

## 影响

相同人格、配置和工具集合下，system 可以跨轮、跨日保持字节稳定。时间感知、记忆和成员信息继续在当前请求中可见，测试需要分别核对稳定段与动态信封。

新增动态资料应明确其请求级用途和历史保留方式。缓存诊断按真实请求序列化与渠道计量观察；历史表达的稳定追加由 ADR-0003 管理。
