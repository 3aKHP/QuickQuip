# ADR-0012：将动态轮次信息放入当轮信封

- 记录日期：2026-10-23
- 原始决策日期：2026-09-03；方案于 2026-09-04 完成评审定稿

## 背景

模型请求的 `system` 提示词曾包含时间、参与者、记忆和词表命中。这些内容随每轮变化，使稳定的人格与行为要求也无法形成可持续复用的请求前缀；日期变化还会改变跨日请求。

与此同时，机器人仍需要获知当前时间与群内现场资料，因此需要将跨轮稳定的指令前缀与仅属于当轮的动态信息分开安放。

## 决定

`system` 提示词仅保留人格、风格、消息解释与工具使用规则等稳定内容。当前时间、节日、参与者、相关记忆及词表命中在组装请求时放入当轮 `user` 消息头部的“轮次上下文”信封。

信封仅在组装当轮请求时渲染并随该次 Agent Loop 发送，落库与跨轮历史回放只保存去除信封后的规范化用户消息，使历史片段不受当轮临时上下文污染。

## 方案与理由

保留动态 `system` 内容会让时间和资料变化持续改写请求头部。将其移到当前轮次末端，可以同时表达稳定要求和最新事实，并为支持前缀缓存的渠道提供稳定输入。

当时也评估过显式缓存标记及逐字原始请求重放，最终决定先理顺提示词的内容归属，再与纪元窗口和上下文预算配合推进。

## 影响

在相同人格、配置和常驻工具集合下，`system` 提示词可以跨轮、跨日保持字节稳定；时间感知、记忆召回和成员信息仍在当轮请求中完整可见，测试需分别核对静态前缀段与动态信封段。

后续新增动态上下文字段时，应明确其仅限当轮消费还是需要进入持久化历史。前缀缓存收益通过真实协议序列化回归与渠道返回的缓存计量指标核对；历史消息表达的稳定追加见 [ADR-0003](0003-epoch-history-freezing.md)。
