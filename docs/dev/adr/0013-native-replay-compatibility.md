# ADR-0013：按归属与结构校验选择原生回放

- 记录日期：2026-10-23
- 原始决策日期：2026-09-14（Responses 跨轮回放方案）

## 背景

Agent 执行记录可以保存协议层的原生状态块，例如思维签名、加密推理条目与原生工具调用结构。若跨轮一律退化为纯文本摘要，模型会丢失推理链与原生工具续接状态；但若不加区分地把旧轮次保存的原生块直接发往其他渠道、模型或协议端点，又可能触发签名验签失败、调用 ID 冲突或工具声明与结果配对残缺。

历史投影因此需要在“复用高保真协议原生块”与“回退为跨协议通用的结构化或文本表达”之间建立明确的准入判据。

## 决定

跨轮原生回放必须同时满足“请求归属精确一致”与“发送前结构校验通过”两项前提：

- **归属匹配**：由渠道 ID、协议类型、实际请求模型、上游端点以及影响请求结构的协议 Profile 指纹共同构成归属标识（Owner）；任一要素不匹配或无法确认兼容时，历史轮次自动按目标协议转换为通用工具消息或纯文本工具档案。
- **发送前结构校验与单次降级重试**：以 OpenAI Responses 为例，发送前先静态检查历史 `call_id` 是否冲突、工具声明与输出是否完整成对，并将不合规的历史 Loop 单独降级。若上游接口仍因历史原生条目的结构或签名不兼容返回 HTTP 400 等请求校验拒绝，适配器可在请求副本上将历史推理／签名条目降级后自动重试一次；当前正在执行的工具循环内新生成的原生条目则始终按协议保留，确保当轮工具调用链完整续接。

## 方案与理由

一律回退纯文本会浪费同渠道连续对话的原生推理续接能力，无条件原样重放又会把请求成败寄托在不同端点恰好兼容的脆弱假设上。通过归属指纹加本地结构预检过滤已知不兼容场景，再用单次有界降级重试兜底上游特有的结构或签名校验拒绝，能够兼顾同源对话的原生体验与切换模型时的稳健回退。

## 影响

切换模型、变更上游端点或调整能力 Profile 时，同一段历史记录会按新归属自动切换投影路径。由于上下文预算裁剪与敏感词清洗同样可能改变原生回放资格，发送前校验与降级重试均在单次请求副本上执行，不回写数据库中的权威记录或纪元冻结快照。

每次实际发出的 HTTP 请求独立计入用量统计与诊断日志；降级重试仅在命中历史原生结构或签名校验拒绝时触发一次，鉴权错误、配额耗尽与常规网络异常直接按标准失败路径返回。
