# ADR-0019：通过共同配置基线协调双向同步

- 记录日期：2026-10-24
- 原始决策日期：2026-10-24

后续决定见 [ADR-0024：工作副本与单向配置部署](0024-directional-configuration-deployment.md)。

## 背景

管理员既会在本地开发机编辑配置并部署上线，也会通过服务器上的 Web Admin 直接热修线上配置。由于 LLM 配置存储在 SQLite 数据库中、人格与规则等配套文件位于磁盘目录，仅对比本地与服务器当前的最终内容，无法判断差异究竟来自哪一端的新增修改；同步流程还需妥善处理文件原子替换、Bot 配置加载确认以及中途 SSH 连接断开等异常情况。

## 决定

在每一对本地与远端环境之间维护完整的共同配置基线，通过“共同基线、本地当前草稿、服务器已发布快照”三方比较协调双向同步：

- **规范化同步包**：同步包由规范化的 LLM 配置文档与受管文件资产组成，其内容摘要仅由逻辑配置内容计算，排除数据库修订号、跨进程控制任务与进程心跳等运行态字段。
- **冲突裁决与基线推进**：当同一配置单元在两端相对共同基线均发生修改时，必须由调用方显式指定覆盖方向。执行写入时携带修订号与内容摘要校验，并对服务器后台尚未发布的独立草稿单独加以保护；持久化的维护状态锁负责在同步期间互斥阻塞应用内的并发配置写入，待目标配置成功应用且部署结果确认后，再前推两端共同基线。同步操作日志与恢复备份保存在独立的私有状态目录中。

## 方案与理由

若长期将本地或服务器硬性固定为唯一权威源，就无法兼顾“本地批量改配置推上线”与“线上紧急热修回流本地”两种日常工作流；若直接拷贝替换整个 SQLite 数据库文件，又会把对方正在运行的任务队列和进程心跳一并抹除。提取逻辑配置包并引入共同基线，既能准确判定变更方向，也为后续在 JSON 交换层与本地 TOML 工作副本之间复用同一套比较、校验和提交逻辑打下基础。

首期实现以“整份 LLM 配置文档”和“单个受管文件”作为冲突检测粒度，字段级差异仅用于终端审阅提示，跨对象引用与有序列表的字段级自动合并留待后续迭代；可逆 TOML 工作副本适配规划在二期落地。

## 影响

常规部署在首次建立共同基线后即可自动识别并同步单侧配置变更，并在受管文件更新时按需触发受控重载或重建；根目录 `.env` 通过独立的来源策略开关管理。处于同步维护窗口期间，后台配置写接口返回忙碌提示，中途失败的同步事务必须先完成回滚恢复或人工确认后才能解除维护锁。跨进程加锁顺序、SSH 断线重试幂等性以及双端基线确认顺序成为实现与测试的重点约束。
