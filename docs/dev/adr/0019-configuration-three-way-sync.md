# ADR-0019：通过共同配置基线协调双向同步

- 记录日期：2026-10-24
- 原始决策日期：2026-10-24

## 背景

本地编辑与服务器 Web Admin 都会修改配置。LLM 配置发布于共享数据库，配套文件位于版本目录；仅比较两端当前内容，无法判断哪一端包含新的修改。部署还需要处理文件替换、Bot 应用确认和客户端连接中断。

## 决定

每对端点保存完整的共同配置基线，按基线、本地草稿与服务器已发布内容进行三方比较。同步包包括规范化配置文档和受管文件资产，内容摘要独立于数据库修订、运行任务和心跳。

同一单元的双方分歧需要明确处理方向。覆盖携带修订和内容检查；后台未发布草稿单独保护。持久化维护状态协调应用内写入口，目标应用与部署结果确认后推进基线。操作日志与配置恢复副本保留在独立私有目录。

## 方案与理由

固定选择本地或服务器为长期权威，无法同时满足本地更新与线上热修回流。直接交换数据库文件会连同任务和运行状态一起替换。配置包和共同基线使同步方向可解释，也让 JSON 和未来 TOML 簇共享比较、校验和提交能力。

一期采用整份 LLM 文档及单个文件作为冲突单元。字段级差异用于审阅；对象引用和有序级联的自动合并需要另行设计。TOML 往返适配在二期实现，保持类型、空值、顺序与资产内容的完整性。

## 影响

普通部署建立基线后自动同步，文件变更可触发受控重建。根 `.env` 由独立来源选项管理。维护中的配置写入返回忙碌状态，失败操作必须恢复或确认后解除。跨进程锁顺序、SSH 重试幂等和两端确认顺序成为后续修改的验证重点。
