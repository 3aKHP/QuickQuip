# TOML 配置工作副本契约

本文面向配置转换与恢复流程的维护者。操作入口见[管理员指南](../admin/config-workspace.md)，决策见[ADR-0020](adr/0020-editable-configuration-workspaces.md)。

## 内容格式

工作副本版本 1 适配配置包版本 1、LLM 文档版本 2。转换保留规范化文档的 JSON 值类型、缺失、空值、顺序、引用和资产字节。SQLite 页、历史、任务及心跳继续属于数据库持久状态。

`workspace.toml` 的封闭字段为 `format_version`、`document_format_version`、`providers`、`settings`、`styles`、`routes`、`pricing` 和 `assets`。

- `providers` 是有序渠道文件路径列表，模型与别名内嵌渠道正文。
- `settings`、`styles` 是 `{id,file}` 列表，各组 ID 唯一。
- `routes`、`pricing` 固定引用 `routes.toml`、`pricing.toml`。
- `assets` 是一期受管路径列表，对应 `assets/<路径>` 原始文件。

逻辑文件只有 `value` 根。文件名使用清洗后最长 48 字符的可读前缀及原 ID 的 SHA-256 摘要；摘要从 12 位开始按 4 位递增以消除碰撞。正文身份与清单决定组装结果。

## 值编码与文本维护

TOML 原生值直接映射；日期时间和非有限浮点不属于配置值域。保留键为 `__quickquip_value__`：

| 配置值 | 编码 |
|---|---|
| `null` | `{ __quickquip_value__ = "null" }` |
| 超出有符号 64 位的大整数 | `{ __quickquip_value__ = "integer", decimal = "1237940039285380274899124224" }` |
| 包含保留键的用户对象 | `{ __quickquip_value__ = "object", entries = [{key = "...", value = ...}] }` |

对象条目递归使用同一编码，键保持字符串且禁止重复。整数标签采用规范十进制拼写。标签字段与组合严格校验，防止与用户对象混淆。

无变更文件逐字节保留。更新使用 tomlkit 既有节点，模型与别名等表数组按唯一身份匹配；删除节点原文保存在操作恢复资料中。输出经 `tomllib` 复核，再重新组装比较配置包摘要。

## 计划与提交

工作副本基线、工作树和本地草稿/资产参与一期三方比较。LLM 文档整体和单个资产各为比较单元；显式覆盖采用一期 push/pull 完整来源选择规则。

`plan_hash` 绑定方向、覆盖选项、来源根、来源版本、工作副本状态及受管文件字节摘要。执行前重新生成并比对计划。修订未增长的 SQL 修改还受正文摘要与投影一致性校验保护。

刷新把组合结果写回工作树，以当前数据库包为新基线。组装提交目标草稿和资产，以提交结果为新基线。正文与资产无变化时保持数据库修订。

## 恢复与存储边界

`.quickquip/state.json` 保存来源及基线，操作日志保存前后文件、状态与来源租约。活动操作阻止普通命令继续，文件写入使用私有权限、替换和 fsync。

源组装复用 `Endpoint.prepare(..., local_only=True)` 和 `commit`。`complete_local` 检查目标后解除维护，不写 peer、不推进远程基线，RPC 不暴露此完成入口。

顺序为工作副本准备 → 源准备/写入 → 工作文件及基线写入 → 源本地确认 → 工作副本回执。源确认是提交点，补回执保留之后的新修改。源写入不确定时要求恢复，避免重复提交。

源恢复沿用一期备份及外部修改检查，已开始写入时要求停止服务。工作文件恢复允许执行前或目标内容，第三种内容阻止覆盖。刷新恢复只处理工作副本。

路径先检查符号链接，再规范化后校验活动目录边界；输入校验清单、跨平台名称、大小写碰撞、总容量及文件类型。资产继续使用一期范围和领域解析器。
