# qqconf 本地配置工作副本契约

本文面向配置工具维护者，说明 `qqconf` 工作副本的目录契约、TOML 值编码、三方合并规则及崩溃恢复机制。日常命令用法与受管文件清单见[管理员指南](../admin/config-workspace.md)，架构决策依据见 [ADR-0022](adr/0022-local-configuration-workspace-cli.md)。

## 职责与布局

`quickquip.config_workspace` 提供命令行工具 `qqconf unpack|refresh|pack` 及等价的 Python 模块入口，用于在本地真实配置与人类可读的工作副本之间双向转换；远端同步工具 `qqsync` 只读取真实配置或候选目录，不直接消费工作副本。受管配置中，`config/managed/config.db`（SQLite schema 4）的可编辑业务内容会拆分为工作副本 `db/` 目录下的多份 TOML 文件，其余独立配置文件保持原有的相对路径和文件格式。受管配置项由 `quickquip.configuration.inventory` 统一发现，工作副本内的目录映射由 `config_workspace.layout` 管理，新增受管项无需逐文件手工登记。

职责划分上，`quickquip.configuration` 负责构建配置逻辑快照、执行字段级合并、保留原格式文本及安装持久化文件；`quickquip.config_workspace` 独立负责工作副本的 TOML 值编码、目录布局、编辑基线维护与本地事务恢复。

工作副本元数据保存在 `.qqconf/state.json`（格式版本 `2`），记录绑定来源根的绝对路径、三方合并共同基线及最近生成的候选目标。渠道、共享风格与作用域覆盖均以正文内的业务 ID 作为唯一身份；导出的文件名优先采用可读名称，发生重名碰撞时自动追加数字后缀。渠道顺序文件为可选项，新增渠道自动追加到末尾；模型列表与模型别名列表严格保持文档内的声明顺序。

## 值编码与文本保留

导出固定可选字段时，`None` 会直接省略，读取时按字段定义恢复默认值；日期时间与非有限浮点数（`NaN`、`Inf`）不在 LLM 配置文档的值域内。常规标量、数组与表直接映射为原生 TOML 值。由于 TOML 语法没有原生的 `null` 字面量且整数范围限于有符号 64 位，任意 JSON 载荷（如 `extra_body`）中的特殊值统一使用保留键 `__quickquip_value__` 编码；若用户自定义对象本身恰好包含 `__quickquip_value__` 键，则包裹为键值条目列表以避免语义冲突：

| 配置值 | TOML 表示 |
|---|---|
| `null` | `{ __quickquip_value__ = "null" }` |
| 超出有符号 64 位的大整数 | `{ __quickquip_value__ = "integer", decimal = "1237940039285380274899124224" }` |
| 含保留键的用户对象 | `{ __quickquip_value__ = "object", entries = [{key = "...", value = ...}] }` |

嵌套条目递归套用上述编码规则，大整数统一采用规范十进制字符串表示，业务顶层字段直接平铺在 TOML 文件根部。

写回未发生语义变更的文件时，工具保持原始字节不变。需要局部更新时，各格式按自身语法树保留周边文本：

- **TOML**：在既有语法节点上原地更新，表数组按业务稳定身份匹配，紧邻表头的注释随对应条目一并移动；三方合并产生变更时优先保留工作副本侧的排版与注释，工作副本未改动的部分采用真实来源原文。
- **YAML**：局部修改目标节点后重新解析复核语义一致性。
- **dotenv（`.env`）**：保留未修改行的键值绑定与注释，读取时按字面量解析而不做变量展开。
- **JSON**：保留原有的缩进风格；被修改对象的内部键序可能随序列化重排。

## 三方合并与基线

执行同步时，工具以共同基线 `B`、工作副本树 `W` 与真实配置来源 `R` 执行三方合并，生成目标快照 `T`：

- 两端做出相同修改或仅单侧发生修改时，直接采纳修改结果；字典映射递归下探到叶子字段。
- 集合元素按业务身份对齐：渠道与循环定时任务按 `id`、模型按 `model`、别名按 `alias`、价格按 `(provider_id, model)` 匹配。同一对象内不同字段的独立修改可自动合并；路由候选级联与普通数组作为有序整体比较。
- 一侧删除而另一侧修改同一对象，或两侧将同一字段改为不同值时，记录合并冲突并默认中止整次写入。显式传入 `--prefer workspace` 或 `--prefer source` 时，仅在冲突位置按指定侧裁决，非冲突修改照常保留。

合并得到的目标快照 `T` 会结合目标环境内的人格文件、请求指纹 Profile 及跨文档引用完成整体校验，因此新增渠道与引用该渠道的群组覆盖可以在同一次 `pack` 中一并提交。校验针对目标配置草稿执行：`qqconf` 只更新受管配置文件、数据库草稿或本地候选包，在线发布与运行时状态仍由 Web Admin、`qqsync` 及运行中的 Bot 进程管理。

领域解析器在独立的环境变量展开上下文中校验目标快照：优先读取目标 `.env` 中的定义，未声明的变量回退读取当前进程环境；校验结束后立即还原上下文，落盘文件与终端预览均保留原始 `${VAR}` 引用字样。

| 操作 | 工作树结果 | 新基线 |
|---|---|---|
| `refresh` | 不写入 | 保持不变 |
| `unpack` | 更新为合并结果 `T` | 推进为真实来源 `R` |
| `pack`（写入真实配置） | 更新为合并结果 `T` | 推进为合并结果 `T` |
| `pack`（写入候选目录） | 更新为合并结果 `T` | 保持为 `R`，并记录候选目标 |

候选目录 `.config-staging/` 不参与下一轮来源比较。`refresh` 只读取当前状态与候选摘要用于展示，不执行中断事务恢复，也不推进基线。若合并前后内容完全一致，工具保留原有的配置修订号、时间戳与文件字节。终端预览默认遮蔽 `.env` 取值与敏感字段，传入 `--show-secrets` 仅在当次标准输出中显示明文。

## 服务状态与锁协调

Bot 与 Web Admin 从标准入口启动并在读取配置前获取 `configuration.activity` 生命周期锁，进程退出或异常终止时由操作系统自动释放。`qqconf` 执行离线真实写入期间会同时持有这两把生命周期锁，阻止服务在写入中途启动；同时获取公共配置维护锁（若存在未完成的真实配置中断记录，同样会阻止新的配置写入与服务启动）及工作副本自身的写锁。

写入目标位置由真实根目录 `.env` 中的 `QUICKQUIP_DEPLOY_LOCATION` 决定，且写命令要求显式配置 `QUICKQUIP_DEPLOY_RUNTIME=source|docker`：

- `QUICKQUIP_DEPLOY_LOCATION=cloud`：在成功获取 Bot 与 Web 两把生命周期独占锁后直接写入真实配置文件与配置库，以实时锁状态作为停服依据。
- `QUICKQUIP_DEPLOY_LOCATION=local`：始终将合并结果写入 `.config-staging/` 候选目录供 `qqsync` 后续同步；本地服务运行状态仅用于状态提示，不改变写入目标。

只读查询 SQLite 配置库时，工具先将稳定的主库文件及配套 WAL／journal 复制到临时目录再打开读取，避免在真实配置目录产生临时读写副作用。准备写入目标配置库时，工具先备份原库，按合并结果更新草稿、关系投影、作用域覆盖与游戏文案模式并保留本环境的配置历史；仅当配置文档正文实际发生变化时才递增配置修订号，最后通过 SQLite backup API 写回目标库以兼容既有 WAL 状态。

## 写入与恢复

三类写入操作各自维护独立的事务日志，记录写入前内容（**前像**）、目标内容（**后像**）及内部提交回执，通过原子文件替换与目录级 `fsync` 保证落盘顺序：

- 工作副本更新日志：`.qqconf/transaction.json`
- 真实配置写入日志：`data/qqconf/active.json`
- 候选目录替换日志：`data/qqconf/staging.json`

真实配置的写入顺序为：写入事务日志 → 安装真实文本配置与 SQLite 配置库 → 在工作副本状态中记录提交回执并更新基线 → 清理事务日志。候选目录的替换顺序为：完整写入 `.config-staging.new/` → 将旧候选移至 `.config-staging.previous/` → 原子切换为 `.config-staging/` → 确认工作副本状态并清理旧目录。生成的 `candidate.json` 记录来源根、真实基线、受管文件清单及待删除列表供 `qqsync` 读取，不包含任何工作副本路径。

由于外部编辑器或手工 SQL 操作不会遵循 `qqconf` 的锁机制，工具在正式提交与崩溃恢复前都会重新读取目标文件或数据库，核验其当前内容是否仍等于事务记录的前像或后像：

- 若工作副本尚未记录提交回执且目标仍为前像或部分写入的后像，恢复流程将其回滚到前像（候选替换则还原 `.config-staging.previous/`）；若已记录提交回执，则保留已完成结果及后续新增编辑，仅清理残留日志。
- 若重读发现目标内容既不匹配前像也不匹配后像（即锁外外部修改产生了第三种状态），工具立即中止覆盖并保留现场，交由维护者人工核对。

运行期捕获普通异常时会自动触发上述恢复；若进程意外终止，下一次针对同一来源路径执行写命令时会自动完成恢复（`refresh` 仅提示存在待恢复事务）。恢复真实配置写入同样要求确认服务已停止并持有生命周期锁；工作副本与候选目录的恢复只涉及本地暂存文件，与线上运行态互不影响。
